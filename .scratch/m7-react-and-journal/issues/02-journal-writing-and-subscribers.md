# 02 — Journal 的寫入與訂閱者

**What to build:** 讓任何一條執行緒都能直接寫進 Journal，而且同一份紀錄能同時餵給不只一個消費者。

**寫入加鎖，任何執行緒直接寫。** 不採「丟進佇列由主迴圈收」的做法 —— 那會讓緊急停止**發生的時間**與**被記下的時間**差開，而那個差距正是我們要量的東西。寫一行 JSON 的鎖競爭極短。

**至少要有兩個訂閱者，否則這個抽象沒有被證明過。** `PLAN.md` §4 說終端機輸出應該退化成「其中一個渲染器」；只有一個訂閱者的訂閱機制是假的。兩個是：JSONL 檔案，以及人可讀的終端機輸出。

**一個訂閱者壞掉不該弄死 Episode。** 渲染器丟例外時，機器人不應該因此停在半路。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 寫入是執行緒安全的；多執行緒並行寫出的檔案每一行都完整且合法
- [ ] 至少兩個訂閱者同時運作：JSONL 檔案與終端機渲染器
- [ ] 有測試以真的並行寫入證明不會交錯損毀，而不是只證明單執行緒可用
- [ ] 訂閱者拋出例外時，寫入者與呼叫端不受影響，且該失敗本身可被觀察
- [ ] 終端機輸出人可讀，且不是 JSONL 的逐欄複製
- [ ] 記下的時間是事件發生的時間，不是被處理的時間
- [ ] 測試在專案 venv 下零 skip
