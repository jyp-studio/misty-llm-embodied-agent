# 05 — 真值軌跡重放,產出 trace

**What to build:** 跑一段「使用者從 150 公分走近到 60 公分」的情境,結束後手上有一份
逐筆紀錄:每個時刻的真值距離、系統當下回報的距離、以及各自的時間。

到 04 為止只能產生單張影格。這一張把它變成一條在真實時間軸上流動的串流,穿過真實的
感知路徑(真的 MediaPipe、真的緩衝、真的中位數濾波),並把兩條曲線錄下來。

**軌跡要涵蓋控制律真的會遇到的情況**,三段各自曝露不同的缺陷:

- **單調接近** —— 距離持續下降。曝露 A1/A2:積壓越深,回報的距離越落後真值
- **抵達後停滯** —— 距離不再變化。作為對照組:靜止時延遲看不出來,這正是缺陷至今
  沒被發現的原因
- **階躍** —— 距離瞬間跳變,對應機器人移動一步之後視野瞬變。曝露 A3:舊樣本仍在
  中位數視窗裡,讀數會卡在舊值

**必須以真實時間節奏注入。** 不加虛擬時鐘——MediaPipe 的真實耗時就是被量的現象本身,
把時間虛擬化等於把主因假設掉。代價是這一段跑得比較久,這個代價是必要的。

這一張只負責「跑完並錄下來」,不負責下結論。判讀是 06 與 07 的事。

> 留證據給碼錶量,而專案已改為重寫而非修補,不再需要證明舊 code 壞掉。
>

> ——兩者都可以,但要選一個並寫下理由,不要默默用 150cm。
