# 09 — 時間軸：動畫、重播、展開、機器人狀態

**What to build:** 「好看」那部分。

**頁面重播完整的 Journal，不做串流。** Episode 跑完之後整份交給頁面，由頁面沿時間軸動畫
展開。視覺結果相同（Episode 本來只有幾秒），但它讓**內建範例與真實執行走完全相同的路徑** ——
省掉一整組串流機制與它的 seam。

主體是**決策時間軸**：觸發 →（想了多久）→ 選了什麼 Tool、帶什麼參數 → 看到什麼 → 下一輪。
旁邊一個小的機器人狀態圖跟著走。

給申請材料看的話，**「我可以指著任何一個決定說出它為什麼發生」比「機器人動起來很可愛」有
說服力得多** —— 所以時間軸是主角，機器人是配角。

**Blocked by:** 08

**Status:** ready-for-agent

- [ ] 時間軸一步步展開，不是一次全部出現
- [ ] 可以重播，不需要重跑（也不需要再付一次模型的錢）
- [ ] 點任何一筆紀錄可以展開看到原始欄位 —— 「可追溯」不只是一句話
- [ ] 被拒絕的呼叫在畫面上明顯，且看得到理由
- [ ] Episode 的結束方式在畫面上明顯（自己停 / 撞上限 / 被中止 / 出錯）
- [ ] 機器人狀態圖（燈色、頭部角度、手臂位置）跟著時間軸變
- [ ] 每次模型呼叫的耗時與 token 數看得到
- [ ] 仍然零新相依
