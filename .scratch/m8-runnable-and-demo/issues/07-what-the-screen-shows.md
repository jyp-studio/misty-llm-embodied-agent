# 07 — 畫面資料（view model）

**What to build:** 決定「畫面上顯示什麼」，而且讓那個決定**落在 pytest 蓋得到的範圍內**。

一個純函式：Journal 的紀錄進去，可序列化的顯示結構出來 —— 每筆紀錄怎麼呈現、時間軸怎麼排、
機器人狀態（燈色、頭部角度、手臂位置）在每個時間點是什麼。JavaScript 只負責畫。

**這是這個里程碑的測試策略核心。** 相反的做法（伺服器只丟原始 JSONL、JS 自己解讀）會讓
「畫面顯示什麼」完全沒有測試 —— 而這個專案剛因為 `TerminalRenderer` 印出 `-> , 52cm away`
學到那一課：不是沒被測到，是測試蓋不到那一層。

**Blocked by:** 02

**Status:** ready-for-agent

- [ ] 純函式，紀錄進、可序列化的結構出。不產生 HTML、不含排版
- [ ] 每一種紀錄都有對應，且有測試證明新增一種而忘記處理會變紅
- [ ] 被拒絕的 Tool 呼叫與**拒絕的理由**出現在結構裡 —— 看得到 agent 犯錯以及系統如何擋下來
- [ ] Episode 的四種結束方式在結構裡是可分辨的
- [ ] 機器人狀態隨時間軸演變（哪一個 Turn 之後燈是什麼顏色、頭轉到哪裡）
- [ ] 每次模型呼叫的耗時與 token 數在結構裡
