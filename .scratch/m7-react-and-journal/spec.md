# M7 — ReAct 迴圈與 Journal

Status: ready-for-agent

> 上游脈絡：`PLAN.md` §4（ReAct 設計）、§7（里程碑 M7）、§13（M5 的窄介面）、
> §14.1（M6/M7 重整與 ticket 順序）、§14.6（M6 刪除舊 runner 欠下的兩筆帳）、
> §14.7–§14.11（M6 量出來、仍然成立的約束），以及 `CONTEXT.md` 的詞彙。
> 本 spec 使用 `CONTEXT.md` 的詞：Episode、Turn、Step、Tool、Journal、Event、
> Observation、Snapshot、Exchange、Reading。

---

## Problem Statement

這個專案叫「LLM 具身 agent」，但**那個 agent 現在不存在**。

M5 交付了可信的 `approach()` 後端，M6 用 1830 個網格點證明它在多大的參數範圍內站得住。
可是打開程式碼會發現：**呼叫 `approach()` 的只有測試與量測台**。沒有任何東西會因為「使用者
說了一句話」而決定要不要靠近。中間那一層 —— 決策 —— 是空的。

舊主腳本裡有一個 brain，但它不是 ReAct：它一次呼叫 LLM、拿回一個 JSON、執行、結束。沒有
觀察、沒有第二輪、沒有「上一步失敗了所以改做別的」。它也已經是唯讀參考（`PLAN.md` §12.3），
新工作不得再依賴它的感知或 approach 實作。

**而且沒有 Journal，就沒有辦法主張任何事。** LLM 的行為要用什麼斷言？步數與延遲要用什麼量？
未來的 UI 要訂閱什麼？`PLAN.md` §4 早就指出這三件事共用同一個模組，而它還沒被寫出來。

M6 還留下兩筆明確的帳（§14.6）：memory 折疊與持久化的覆蓋、以及工具參數的合法性檢查。
兩者在 M7 完成前都沒有可執行的覆蓋。

## Solution

把決策層補上，並且讓它從第一天起就是**可被斷言的**。

交付一個有界的 Episode：`run_episode(觸發輸入)` 進去，結構化結果出來。過程中每一件值得記錄
的事都成為一筆型別化的 Journal 紀錄 —— Turn 的開始、模型呼叫、Tool 呼叫、Observation、
Episode 如何結束。JSONL 是那些型別的**序列化格式**，不是契約本身。

LLM 透過 9 個 Tool 行動，參數由型別定義並在送到機器人之前驗證。**分層原則是硬的**：LLM 決定
「要不要靠近、失敗了改做什麼」，控制層決定「這一步走幾公分」。velocity 與 timeMs 全程不在
模型的視野裡。

Memory 重新設計成「一份只增不改的 Exchange 紀錄是唯一真相，摘要與事實是它的衍生物」，並把
兩次 LLM 呼叫從「每個 Turn 一次」移到「每個 Episode 一次」。

**Ticket 順序是這份 spec 的一部分，不是建議**（`PLAN.md` §14.1）：

```
spec  →  Journal 型別 + golden files（先 commit）  →  tools / react  →  最後刪舊主腳本
```

Journal 是 M7 測試的斷言標的。如果它與 ReAct 迴圈在同一批工作裡長出來，斷言的詞彙就會被
實作反向塑形 —— 會寫出「剛好會過」的測試。Schema 必須**從這份 spec 推導，不從實作推導**。

## User Stories

1. 身為使用者，我想讓機器人在一次互動中可以連續做好幾個動作，這樣它的反應不只是一次性的單一指令。
2. 身為使用者，我想讓機器人在某個動作失敗後改做別的，而不是照著原本的計畫繼續，這樣失敗不會變成呆滯。
3. 身為使用者，我想讓每一次互動都在有限步數內結束，這樣機器人不會卡在無止盡的嘗試裡。
4. 身為使用者，我想讓機器人自己判斷「不需要再做什麼了」，這樣簡單的問候不會被硬拖成多輪。
5. 身為使用者，我想讓緊急停止在任何一個 Turn 都能中斷互動，這樣安全機制不依賴 agent 的配合。
6. 身為使用者，我想讓機器人記得我上次說過的名字，這樣它不會每次都重新認識我。
7. 身為使用者，我想讓機器人在講話期間不要把自己的聲音當成我的話，這樣它不會自問自答。
8. 身為使用者，我想讓機器人在講完話之後立刻能聽到我插話，這樣對話不會有一段死時間。
9. 身為 ReAct agent，我想在每一步之後收到動作結果與當下的 Snapshot，這樣我能根據世界的最新狀態決定下一步。
10. 身為 ReAct agent，我想讓失敗的 Tool 回傳可區分的原因，這樣「找不到人」與「走不到」會導向不同的下一步。
11. 身為 ReAct agent，我想只透過 Tool 行動，這樣我的能力邊界是明確且可稽核的。
12. 身為 ReAct agent，我想讓 `approach` 隱藏所有物理細節，這樣我不需要知道速度或時間就能表達「靠近」。
13. 身為 ReAct agent，我想在第一個 Turn 就能結束 Episode，這樣自主終止不是被硬編碼的特例擋掉的。
14. 身為開發者，我想讓一次 Episode 有單一的公開入口與結構化結果，這樣測試不必重建迴圈的內部狀態。
15. 身為開發者，我想讓模型呼叫走一個窄介面，這樣測試可以注入腳本化的回應而不必 mock 第三方套件。
16. 身為開發者，我想讓每個 Tool 的參數由型別定義並自動產生 schema，這樣驗證與宣告不會各自漂移。
17. 身為開發者，我想讓超出範圍或未知的 Tool 參數在送到機器人之前被拒絕，這樣模型的失誤不會變成硬體指令。
18. 身為開發者，我想讓新增一個 Tool 只需要一個函式加一份參數型別，這樣工具集能長大而 ReAct 迴圈不用改。
19. 身為開發者，我想讓 Journal 的每一種事件是一個型別，這樣讀者與測試不需要靠字串鍵去猜結構。
20. 身為開發者，我想讓 Journal 的時間是 Episode 相對秒且時鐘可注入，這樣 golden files 可以逐字元比對。
21. 身為開發者，我想在 Episode 開始那筆紀錄上看到一個絕對時間，這樣人可以把它對到真實世界的時刻。
22. 身為開發者，我想讓 Journal 寫入是執行緒安全的，這樣另一條執行緒上的緊急停止不會寫壞檔案。
23. 身為開發者，我想讓緊急停止被記下的時間就是它發生的時間，這樣中斷的延遲是可量的。
24. 身為開發者，我想讓 Journal 的訂閱者可以有多個，這樣終端機輸出只是其中一個渲染器。
25. 身為開發者，我想讓 Observation 的組裝發生在迴圈裡而不是每個 Tool 裡，這樣 Snapshot 不會被複製九份。
26. 身為開發者，我想讓 memory 的最近視窗是一個純函式的切片，這樣它不需要 LLM 就能測。
27. 身為開發者，我想讓摘要與事實抽取在 Episode 邊界發生一次，這樣多輪的 ReAct 不會讓 LLM 呼叫成倍增加。
28. 身為開發者，我想讓 memory 的持久化是一次資料 dump，這樣存檔不再散在 mutation 裡。
29. 身為開發者，我想讓模型的訊息串與 memory 是兩個東西，這樣一個 Episode 的工作脈絡不會被誤存成長期記憶。
30. 身為開發者，我想把講話時長的估計常數搬進設定並標為未校準，這樣它不再藏在舊腳本裡冒充事實。
31. 身為 CI，我想讓預設的測試不呼叫 LLM、不需網路，這樣它們可以在每個 push 執行。
32. 身為 CI，我想讓需要真 LLM 的測試預設被排除，這樣不確定的行為不會變成會抽風的 gate。
33. 身為開發者，我想讓真 LLM 的測試斷言 Journal 上的不變量而不是模型講了哪些字，這樣它不會因為換句話說而變紅。
34. 身為開發者，我想讓 golden files 涵蓋 Episode 的每一種結束方式，這樣沒有一條路徑缺少對照。
35. 身為履歷讀者，我想看到 LLM 的能力邊界是由程式碼強制的而不是靠 prompt 拜託，這樣分層主張是可驗證的。
36. 身為履歷讀者，我想看到 golden files 的 commit 早於實作，這樣「測資不是事後補的」有客觀證據。
37. 身為接手的 agent，我想讓舊主腳本在 M7 結束時消失，這樣不再有第二套感知與 approach 實作可以誤用。
38. 身為接手的 agent，我想讓 M7 嚴格停在單次 Episode，這樣外層的語音迴圈可以獨立處理它自己的已知問題。

## Implementation Decisions

### 範圍

- M7 的公開入口是**單次 Episode**：接受一個觸發輸入，回傳結構化結果。**不做**「一直等使用者
  說話」的外層迴圈。外層依賴語音串流，而轉錄與 VAD 擠在同一條執行緒上是一個尚未處理的已知
  缺陷；把它拉進來等於在沒修的地基上疊東西。
- Episode 的定義沿用 `CONTEXT.md`：從外部觸發開始，到 agent 回到閒置為止，保證有界終止。
  內部階段不入定義。

### Tool

- **工具集定為 9 個**：`speak`、`display_image`、`move_arms`、`move_head`、`change_led`、
  `play_audio`、`look_around`、`approach`、`done`。
- **`back_up` 砍掉。** `approach()` 本來就會後退——主體太近時它自己會退，M5 已有測試證明。
  兩個 Tool 做同一件事，模型會挑錯，而且從 Journal 上看不出它為什麼挑錯。將來若真需要
  「請退遠一點」，那是給 `approach` 加一個受 clamp 的目標距離參數，不是加第二個 Tool。
  `PLAN.md` §4 的「12 個左右」是 M0 的估計，現在有實際控制層了，估計讓位給事實。
- Tool 以註冊表模式登記。新增一個 Tool = 一個函式 + 一份參數型別，**不動 ReAct 迴圈**。
- **參數用型別定義，schema 由型別產生。** 一份定義同時負責宣告與驗證，兩者不會漂——這個
  repo 已為「兩份會各自漂移」做過至少三次決定。這同時還掉 §14.6 欠的工具參數檢查那筆帳。
- 超出範圍或未知的參數在送達驅動層**之前**被拒絕，並成為一筆 Journal 紀錄。
- **分層原則是硬的**：velocity 與 timeMs 不出現在任何 Tool 的參數裡，也不出現在送給模型的
  任何文字裡。

### Journal

- **每種事件一個 frozen 型別。** 共同欄位只有三個：時間、事件種類、Episode 識別。**`turn`
  不是共同欄位**——Episode 開始那筆沒有 Turn，硬塞會逼出一個 Optional，然後每個讀者都要處理它。
- **時間是 Episode 相對秒，來自單調時鐘，時鐘可注入。** 沿用 `approach()` 既有的 Clock
  protocol 與測試用假時鐘。這讓 golden files 天然可以逐字元比對。Episode 開始那筆額外帶
  **一個**絕對 wall-clock 戳記供人對時；只有一個，不影響其餘可比對性。
- **契約是那些型別，JSONL 是序列化格式。** 版本欄位只放在 Episode 開始那一筆——一個 Journal
  對應一個 Episode，檔案是整份讀的。**M10 之前 schema 不保證穩定**，並明寫這件事：這是履歷
  作品不是發布的 API，假裝穩定要付相容性的代價。
- **寫入加鎖，任何執行緒都可以直接寫。** 寫一行 JSON 的鎖競爭極短。不採「丟進佇列由主迴圈
  收」，因為那會讓緊急停止「發生的時間」與「被記下的時間」差開——而那個差距正是要量的東西。
- 終端機輸出是 Journal 的**其中一個訂閱者**，不是另一條輸出路徑。至少要有兩個訂閱者存在，
  否則這個抽象沒有被證明過。
- 紀錄至少涵蓋：Episode 開始與結束（含結束方式）、每個 Turn 的開始、模型呼叫（含延遲與 token）、
  Tool 呼叫（含參數）、Observation、參數被拒絕、以及緊急停止造成的中止。

### ReAct 迴圈

- **步數上限保留為硬上限。** `PLAN.md` §4 稱「每個 Episode 可證明回到閒置」是這個系統最強的
  性質，而 ReAct 化最容易弄丟它。上限值是初值，用 Journal 量過之後再修。
- **沒有獨立快路徑。** 模型在第一個 Turn 就能結束 Episode；自主終止本來就是 ReAct 的判準，
  硬編碼特例等於自廢武功。
- **Observation = Tool 自己的結果 + Snapshot。** Snapshot 由迴圈附加，不由每個 Tool 各自組裝
  ——它對每個 Tool 都一樣，放進 Tool 就是複製九份。
- Snapshot 就是三樣：主體距離、是否看得見、是否聽到新的話。**刻意固定**，因為三樣本來就在跑，
  零額外模型呼叫、零額外等待。更豐富的感知是**一個模型自己去呼叫的 Tool**，不是加寬 Snapshot
  ——那會讓每一步都付那個成本，而 `PLAN.md` §4 已明確否決每步重跑影像模型。
- **失敗原因靠既有的四個 approach 狀態承載**，不加寬 Snapshot。「人是什麼時候不見的」這種
  脈絡在 Journal 與模型自己的訊息串上已經有了。
- Observation 送給模型時序列化為 JSON。**不並陳一份人話摘要**——同一個事實兩份拷貝會漂。
- 模型呼叫走一個**窄介面**：訊息與工具清單進，一個 Tool 呼叫或一個結束出。memory 的摘要走
  同一個介面，不另開第二個。

### Memory

- **一份只增不改的 Exchange 紀錄是唯一真相**，摘要與事實是它的衍生物。
- **取最近幾輪是一個純函式的切片**，不需要模型，微秒級可測。§14.6 欠的五條檢查大半落在這裡。
- **摘要與事實抽取在 Episode 邊界各做一次**，不是每個 Turn 一次。ReAct 之下一個 Episode 有
  多個 Turn，但使用者只說了一次話——每輪抽取是在對著沒有新東西的紀錄抽。
- **模型的訊息串不是 memory。** 那是一個 Episode 的工作脈絡，隨 Episode 丟棄；Exchange 是跨
  Episode 活著的東西。兩者不得合而為一。
- 持久化是一次資料 dump，不再有散在 mutation 裡的存檔。
- **不引入向量檢索。** 一個 Episode 五到十秒、一次 session 幾十輪，語料規模撐不起嵌入呼叫與
  額外相依帶來的成本。

### 講話與抑制窗

- **`PLAN.md` §4 說「用 `speak` 回傳的 `spoken_ms`」是錯的**：Misty 的 TTS 不回傳任何時間。
  舊腳本用字數估計並已自行標註未校準。
- 保留字數估計，但**把速率常數搬進設定並明列為未校準**——它現在硬編在舊腳本裡。
- 抑制窗**只涵蓋 TTS 播放期間**，不是整段動作期間。靠注入時鐘讓它可測。

### 收尾

- **舊主腳本在 M7 的最後一張票刪除，且單獨一支 commit。** 那個檔案一千多行，刪除的 diff 混在
  其他改動裡，review 會看不出刪掉的是不是正確的東西。
- `PLAN.md` 有五處要一併更正：§4 的 JSONL 範例用 `step` 指 Turn；「12 個左右」的工具數；
  `spoken_ms` 那句事實錯誤；memory 從「搬移」改為「重新設計」；§2 目標結構裡的 `agent/events.py`
  現在叫 `journal.py`。

## Testing Decisions

- 好測試只斷言通過公開介面可觀察的行為。不斷言迴圈的內部狀態、訊息串的組裝細節、註冊表的
  資料結構，或私有方法。
- **主要斷言 seam 只有一個：單次 Episode 的公開入口。** 測試餵它一個觸發輸入，跑完後**斷言
  它產出的 Journal**。M7 的一切都發生在一次 Episode 裡。
- **唯一新增的 seam 是模型呼叫的窄介面。** 測試注入腳本化的回應，不 mock 第三方套件。
- 其餘沿用既有 seam：記錄式 robot adapter、`latest_reading()` 讀數介面、Clock protocol 與
  假時鐘、ASR 的 Transcriber port。
- **Golden files 必須先於實作 commit**，並涵蓋 Episode 的**四種結束方式**：一個 Turn 就結束、
  多個 Turn 正常完成、撞到步數上限、被緊急停止中止。少一種就有一條路徑沒有對照。
- Golden files 由 spec 推導，不由實作推導。實作若產不出某份 golden，改哪一邊是**刻意決定並
  記回 `PLAN.md`**，不是默默改 golden 去配合程式碼。
- 需要真 LLM 的測試掛 marker，**預設排除**，斷言的是**性質不是字串**：步數上限、Episode 必定
  終止、模型從未收到 velocity 或 timeMs、Tool 參數都在範圍內、`approach` 只走確定性後端。
  像「使用者難過時表情是否合宜」那種分開報通過率，**不當 gate**——那會是會抽風的 gate，而 M6
  剛示範過抽風會怎麼侵蝕「全綠」這句話的價值。
- **自己先做 mutation testing 再宣稱測試有效**，並在**隔離的 worktree** 裡做。M6 期間有兩次
  是靠 mutation 才發現覆蓋是空的，也有一次是兩軸 review 平行跑而互相污染。
- Journal 的渲染與 memory 的視窗切片都是純函式，必須可在毫秒內測試、不需模型也不需相機——
  M6 的 `boundary_curve` 與 `build_noise_report` 是既有先例。
- Prior art：`tests/test_approach.py`（公開 seam 上的行為斷言、假時鐘、記錄式 adapter）、
  `tests/test_noise_report.py`（純函式報告、手工列）、`tests/test_drivers_contract.py`
  （對照官方文件的請求格式）、`tests/test_robustness.py`（模型自我驗證與陰性對照）。
- 全部預設測試在專案 venv 執行，不呼叫 LLM、不需網路、不需硬體，且**不得 skip**。

## Out of Scope

- **外層的感知迴圈**：等待語音、VAD、觸發判定。連同 `AudioStream` 轉錄與 VAD 共用執行緒的
  已知缺陷，另立工作。
- **語音輸入本身的品質**：ASR 準確率、噪音處理、麥克風行為。
