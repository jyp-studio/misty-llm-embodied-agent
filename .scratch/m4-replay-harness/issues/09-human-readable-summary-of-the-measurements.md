# 09 — 人可讀的摘要輸出

**What to build:** 一行指令,跑出一份任何人不必架環境、不必讀程式碼就看得懂的報告:
延遲多少、緩衝堆多深、控制律在多大的未知延遲範圍內還能用。

前面八張的產出都是給測試斷言用的機器可讀數字。這一張把它們變成給**人**看的東西。

這不是裝飾。`PLAN.md` §6 說 harness 一份工作要交付四件事,其中兩件是「可跑的 demo」
與「缺陷 A 的證明」——兩件都需要有人看得懂。這個專案是履歷作品,而一個讀 repo 的人
不會為了看一個數字去裝 mediapipe。

**同時要交付的是誠實的邊界敘述。** 這份摘要必須寫清楚它證明了什麼、沒證明什麼:

- 證明的是**截段 B 的時間語意**——從影格進 process 到讀數出來的那一段
- **不證明**真機上的端到端延遲。截段 A(曝光 → 編碼 → RTSP over WiFi)量不到
- 08 的掃描是**參數掃描,不是量測**,沒有任何實機依據

這條線要和 M3 契約測試那條線(證明請求格式正確,不證明機器人會照做)寫成同一種語氣,
M10 改寫 README 時直接沿用。
